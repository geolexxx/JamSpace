# JamSpace — Continue my melody 产品需求文档

- **版本：** 1.1 / v0.2，2026-09-26
- **状态：** 产品范围已修订；功能开发与验收中，完成项须有验证证据
- **目标用户：** 愿意自己写旋律、但在逐小节扩展时失去兴趣的初学者与小型共创小组
- **本次范围：** 从一小节旋律生成三个私有的四小节续写候选，试听后明确接受，继续编辑
- **实现定位：** 本地确定性规则原型；模型支持的 AI 是后续评估项

## 1. 用户问题与依据

用户希望保留写第一小节时的创作乐趣，但不愿在听到完整乐句之前投入大量重复编辑。产品要帮助他们听见自己的想法如何发展，维持继续创作的动力。这是本次用户提出的问题假设，尚无行为数据证明其普遍程度；不能把音乐质量或兴趣提升写成已验证结论。

[README](../README.md) 与 [服务端](../server/src/lib.rs) 描述 Pattern、Track、Note 和共享编辑模型；[客户端](../client/src/components/SessionView.tsx) 提供 Pattern 与轨道编辑。续写应输出普通音符，让用户保留控制权。

**代码现状：** [生成器](../client/src/ai/continueMelody.ts) 已采用本地规则发展动机；[候选面板](../client/src/components/ContinueMelodyDialog.tsx) 提供三个方向的试听和接受入口；[服务端](../server/src/lib.rs) 包含 `apply_melody_continuation` 原子接受逻辑。这些源码不证明已完成部署或双人端到端验收。模型服务、埋点、专用来源标记、整组撤销均未视作已完成。项目权限仍受 1.1 总 PRD 阶段 B 的独立任务约束。

## 2. 目标与边界

1. 让用户在一分钟内从第一小节听到一段更完整的乐句。
2. 保留原小节和其他成员的创作；候选仅在用户接受后共享。
3. 接受后所有新增音符可通过普通编辑器修改。

本次支持 Bass、Synth、Lead 旋律轨道。Bass 是用户可以续写的乐器之一，不承担替用户补齐缺失声部的独立产品角色。

本次不包含：优化或替换原小节、鼓轨续写、整曲生成、任意自然语言编辑、自动发布、独立候选音符编辑器、整组撤销、外部模型调用。未来“优化这段旋律”必须由用户主动发起并单独预览后接受。

## 3. 端到端流程

1. 用户选择当前 Pattern 的旋律轨道，在该轨道写至少一个有效音符；系统以最后一个有音符的小节作为来源。
2. 点击 **Continue my melody** 即生成 **Stay close / Build up / Call and response** 三个候选；面板明确来源小节和接下来的四个目标小节。来源为第 1 小节时，续写为第 2–5 小节，总共五小节。
3. 逐个点击 **Listen**，听原小节、续写和该范围已有伴奏。试听只影响发起人，不改变共享播放状态。
4. 可点击 **Try new ideas**、关闭面板，或 **Apply selected**。未接受候选不保存到共享作品。
5. 接受时由服务端检查来源、目标、Pattern 长度和拍号；成功则一次添加全部音符，必要时延长 Pattern，所有成员看到结果。失败则不添加任何候选音符，原作品保持原样。
6. 用户回到普通音符编辑器继续调整。刷新后保留已经确认接受的结果。

**Pattern 复用提醒：** 延长 Pattern 会影响编排中每一次引用该 Pattern 的段落长度。接受前应告知目标长度；本次不自动创建新的编排段落。

## 4. 功能与验收要求

| 编号 | 要求 | 可测试的验收条件 |
| --- | --- | --- |
| CM-01 | 非鼓轨、来源有音符 | 空小节和鼓轨不能生成，并解释原因；Bass、Synth、Lead 可用。 |
| CM-02 | 固定四小节续写 | 目标恰为来源后四小节；Pattern 最长 32 小节；超过上限时阻止接受。 |
| CM-03 | 保护已有内容 | 目标存在音符或有延音跨入时阻止写入；原小节音高、位置、时值、力度不变。 |
| CM-04 | 三个结构化候选 | 三个方向可试听；音符落在轨道可编辑音域及目标范围，时值为正，力度有效，无重复位置／音高。 |
| CM-05 | 私有试听 | 第二位用户在接受前看不到候选；试听不调用共享播放写操作；本地试听包含原小节和现有伴奏。 |
| CM-06 | 原子接受 | 来源音符改变、目标被占用、Pattern 长度或拍号改变时整次拒绝；Pattern 延长与音符写入同事务。 |
| CM-07 | 协作冲突 | 两人接受重叠目标，至多一人成功；另一人看到冲突提示；不删除队友音符。 |
| CM-08 | 失败可恢复 | 取消、重试、离开、生成异常及服务端错误不修改作品；未部署 reducer 时明确报错，不能逐个写音符冒充成功。 |
| CM-09 | 可编辑与持久化 | 成功接受后可修改、删除单个音符；刷新及另一浏览器看到完整结果。整组撤销不作为本次承诺。 |
| CM-10 | 实现透明 | 原型不调用外部模型；界面／说明能区分规则原型与未来模型能力，不声称已有模型费用或质量保障。 |

**冲突边界：** 当前接受契约比较来源轨道的来源小节、目标范围、长度和拍号。其他轨道修改不被覆盖；若伴奏改变，旧候选的和声适配不保证仍理想，用户可以重新生成。不能声称已冻结或校验整个项目。

## 5. 音乐质量与效果测量

指标均为待验证目标，埋点尚未接入，不能报告已有成功率。

| 指标 | 定义 | 首轮目标 |
| --- | --- | --- |
| 到完整乐句时间 | 来源小节准备好至第一次听到带续写的乐句 | 至少 70% 的测试者 ≤ 60 秒 |
| 本地生成延迟 | 点击生成至三个有效候选显示 | P90 ≤ 2 秒 |
| 接受率 | 至少试听一次的生成会话中接受候选的比例 | ≥ 25%，建立基线后复核 |
| 兴趣保持 | 试听后继续编辑或再次探索的测试者比例 | 先测基线，结合访谈判断 |
| 数据损失 | 生成、试听、接受造成原音符删除或改写 | 0 |

整理至少 20 组输入，覆盖单音、稀疏／密集旋律、重复音、不同速度、4/4、3/4、7/8、来源跨界延音及音域边界。人工评价：是否能听出原动机、是否有发展、结尾是否自然、候选是否有可辨差异、是否愿意继续修改。合法音符不等于好听；三个候选在极窄音域等输入下可能趋同，需记录并评估。

邀请 8–10 组目标用户完成“自己写一小节 → 试听续写 → 自主选择是否接受 → 继续编辑”。记录可用候选和拒绝理由，不把接受率单独作为产品价值证明。

## 7. 发布与决策

当前工作在 `version1.1` 分支开发。源码实现、环境部署、独立验证和产品效果是四个不同状态；开发完成不等于验证了用户问题。原型验收需通过 CM-01 至 CM-10；公开发布另需权限与埋点门槛。

推荐默认：先用确定性规则验证“快速听到自己的完整乐句”是否提高持续创作意愿，再依据盲听和成本对比决定模型接入。外部模型选型与成本上限尚未决定；不会因本次原型开发而默认授权新的付费服务。
