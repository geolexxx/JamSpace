# JamSpace AI Jam Partner — 产品需求文档

- **版本：** v0.1（方案草案）
- **状态：** 待评审
- **首版范围：** AI 为当前 Pattern 生成可编辑的 Bass 声部
- **目标用户：** 2–4 人在浏览器中共同制作音乐草稿的小组

## 1. 背景与问题

JamSpace 已支持多人实时编辑鼓点、旋律、轨道和 Pattern，并在各自浏览器播放同一份作品。待验证的用户问题是：小组做出第一段节奏后，可能卡在“下一条轨道该写什么”。AI Jam Partner 要在这个时刻提供可试听的 Bass 方案，让小组更快得到一段完整、仍可继续编辑的作品。

首版采用结构化音符作为输出，与现有的 `Pattern → Track → Note` 数据模型保持一致。AI 的产出是建议；用户明确接受后才写入共享作品。

## 2. 产品目标

1. 帮助用户从已有节奏或旋律出发，快速补出一条可用的 Bass 线。
2. 保持多人协作的控制感：AI 建议先由发起人私下试听，不打断队友，也不自动覆盖原音符。
3. 让 AI 音符与人工音符一样可以继续编辑、播放和编排。

**首版不包含：** 生成完整音频歌曲、自动发布作品、自动修改其他用户的轨道、聊天式通用音乐助手、跨多个 Pattern 一次生成整首歌。

## 3. 典型用户故事

> 我和朋友已经写好两小节鼓点。我选择当前 Pattern 的 Bass 轨道，点击“AI 补 Bass”，试听三个不同律动的方案，选中一个。朋友立刻看到新增音符，并继续调整其中几个音高。

## 4. 首版范围与交互

### 4.1 入口及生成条件

- 入口位于当前 Pattern 的 Bass 轨道，按钮文案为“AI 补 Bass”。
- 一次只针对当前 Pattern 的连续 1–4 小节生成；用户可选择起止小节。
- 目标范围内已有 Bass 音符时，不允许直接生成覆盖。界面提示用户选择空白范围，或自行清空后重试。
- 当其他旋律轨道有音符时，将其作为和声参考；没有旋律音符时，请用户选择调性后再生成。
- 用户可选一个方向：**稳定、律动、跳跃**。首版不要求输入自由文本。

### 4.2 用户流程

1. 选择 Pattern、Bass 轨道和小节范围，点击“AI 补 Bass”。
2. 选择方向；如缺少旋律参考，选择调性；点击“生成 3 个方案”。
3. 面板展示三个候选。点击任一候选仅在本地试听，并以半透明音符预览其位置。
4. 用户可以“重新生成”“取消”，或“加入作品”。取消不会改变共享数据。
5. 点击“加入作品”时，系统检查目标范围是否仍为空、参考内容是否已发生变化。若有冲突，提示重新生成；否则将整组音符一次性写入共享作品。
6. 所有成员看到新音符及“AI 建议，由〈用户名〉加入”的标记。用户可以像编辑普通音符一样修改它们。在这组音符尚未被其他人修改时，发起人可整组撤销；若已被修改，界面提示冲突，避免删掉队友的新工作。

### 4.3 必须覆盖的边界情况

- 生成超时或失败：保留当前作品，显示可重试提示。
- 候选为空或超出可用音域／小节：不展示为可接受方案，自动重试或告知失败。
- 生成期间队友修改了参考音符或目标范围：允许继续试听旧候选；加入作品时拦截冲突。
- 两人同时生成：两人各自预览；先成功加入者占用目标范围，后加入者收到冲突提示。
- 页面离开或取消：未接受的候选不写入共享作品。
- 播放模式切换：本地试听不能改变全体成员的播放状态。

## 5. 功能与质量要求

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| FR-01 | 生成请求包含当前 Pattern、目标小节、已有音符、BPM、拍号、方向及调性信息。 | 用不同节奏、拍号和小节范围检查请求内容。 |
| FR-02 | 每次返回 3 个结构化音符候选；每个音符具有位置、音高、时值和力度。 | 候选能在现有音序器中预览和播放。 |
| FR-03 | 候选音符必须落在选定范围和 Bass 可演奏音域内，时值为正，不能产生无效或重复音符。 | 服务端校验不合格数据，界面不出现越界音符。 |
| FR-04 | 预览和试听仅对发起人可见、可听。 | 双人测试时，队友界面及共享播放状态不变。 |
| FR-05 | 接受操作以一个完整动作写入；冲突时不写入任何候选音符。 | 双人同时接受、断网及失败重试测试。 |
| FR-06 | 整次 AI 添加可一次撤销，且能识别是谁接受了 AI 建议。 | 音符未被他人改动时可整组撤销；若已被改动，阻止撤销并提示冲突，不删除队友的工作。 |
| FR-07 | 生成失败、冲突、无可用内容时提供明确提示和下一步动作。 | 用户无需刷新页面即可重试或返回编辑。 |

**性能目标（内测目标，技术验证后复核）：** 90% 的请求在 15 秒内出现首批可试听候选。生成期间不阻塞普通编辑和共同播放。

## 6. 数据与实现原则

- AI 调用由服务端处理；密钥和调用配额不放在浏览器。
- 输出采用严格的音符数据格式，并在写入前再次校验。模型输出不可直接作为数据库操作。
- 接受时使用批量写入与冲突检查，避免只同步了一部分音符。
- 为每次 AI 添加记录操作 ID、发起人、目标 Pattern 和音符 ID，以支持归因及整组撤销。
- 只把当前生成所需的音乐片段送入 AI 服务；在接入模型前明确数据保留与费用策略。

## 7. 衡量方式

**主指标：** AI 辅助共创完成率——两位及以上用户编辑同一项目、接受一个 AI 候选，并完成一次共同试听的项目占比。

**过程指标：** 入口点击率、候选试听率、候选接受率、接受后手动修改率、从创建项目到首次完整试听的时间。

**质量指标：** 生成耗时、失败率、冲突率、整组撤销率、音符校验失败率、因 AI 操作导致的原作品数据损失次数（目标为 0）。

首轮建议用 8–10 组双人用户进行任务测试，同时收集“哪个候选可用、为什么”和“哪些部分还要手动改”的反馈；上述指标先建立基线，再定正式上线阈值。

## 8. To-do list（按依赖顺序）

### 阶段 A：定义与设计

- [ ] **T01｜PM｜P0**：确定首版仅支持 Bass、当前 Pattern 的 1–4 小节、三种方向和三个候选。**完成标准：** 范围及不包含项经产品、设计、开发确认，无功能歧义。
- [ ] **T02｜PM + 音乐顾问｜P0**：整理 20 组代表性输入（仅鼓点、鼓点加旋律、不同 BPM／拍号、空 Pattern），写出“可接受 Bass”的人工评价标准。**完成标准：** 每组有预期音域、节奏匹配和可编辑性检查项。
- [ ] **T03｜设计｜P0**：画出入口、参数选择、三候选预览、试听、接受、取消、错误及冲突状态。**完成标准：** 双人使用场景中的私有预览与共享结果区分清楚，并完成可点击原型。

### 阶段 B：基础能力

- [ ] **T04｜后端 + AI 工程｜P0**：定义生成请求和候选音符的数据格式，包含范围、拍号、调性及输出校验规则。**完成标准：** 无效音高、位置、时值和重复音符均被拒绝。
- [ ] **T05｜AI 工程｜P0**：对候选模型或生成方案进行小规模对比，确定首版实现及服务端调用方式。**完成标准：** T02 的 20 组输入均可生成 3 个可解析候选，并记录质量、耗时与单次成本。
- [ ] **T06｜后端｜P0**：实现服务端生成入口、错误处理、超时及基本调用配额。**完成标准：** 浏览器不持有模型密钥；失败不会改动作品；重复请求可追踪。
- [ ] **T07｜后端｜P0**：增加“整组加入 AI 音符”的写入操作，加入时检查参考内容及目标范围是否仍有效。**完成标准：** 成功则整组可见，冲突或失败则不写入任何音符。
- [ ] **T08｜后端｜P0**：记录 AI 添加操作及音符来源，实现整组撤销和改动检测。**完成标准：** 未被他人修改时可整组撤销；若队友已修改这些音符，阻止撤销并提示冲突，不删除队友的工作。

### 阶段 C：界面与联调

- [ ] **T09｜前端｜P0**：实现 Bass 轨道入口和选择面板，并处理缺少旋律时的调性选择。**完成标准：** 已有目标 Bass 音符时阻止覆盖；参数与请求一致。
- [ ] **T10｜前端｜P0**：实现三个候选的本地音符预览和逐个试听。**完成标准：** 第二位用户看不到未接受候选，也听不到试听声音；共同播放不受影响。
- [ ] **T11｜前端 + 后端｜P0**：接通“加入作品”、冲突提示、来源标记与整组撤销。**完成标准：** 双人同时编辑时数据一致，刷新后已接受结果仍存在。
- [ ] **T12｜前端｜P0**：补全加载、空结果、失败、超时、重试和取消状态。**完成标准：** 每种状态都能回到正常创作流程，无需刷新页面。

### 阶段 D：验证与发布

- [ ] **T13｜数据 + 前端｜P0**：埋点生成、试听、接受、取消、失败、冲突、撤销及生成耗时。**完成标准：** 可计算第 7 节各指标，事件不记录不必要的原始作品内容。
- [ ] **T14｜QA｜P0**：完成双浏览器、多用户、慢网、断网、同时接受、跨拍号及不同长度 Pattern 的测试。**完成标准：** FR-01 至 FR-07 全部通过，无原作品数据损失。
- [ ] **T15｜PM｜P0**：组织 8–10 组双人任务测试，复盘方案选择、生成质量和协作感。**完成标准：** 输出主要问题清单与继续迭代／调整方向的决定。

### 后续版本候选（不进入首版排期）

- [ ] **T16｜P1**：自然语言局部修改，如“把这四小节鼓点变稀疏”，仍采用预览后接受。
- [ ] **T17｜P1**：现有 Pattern 的变奏与续写，以及段落编排建议。
- [ ] **T18｜P2**：AI 对多人作品提供具体、可试听的创作反馈。

## 9. 发布门槛

首版进入公开试用前，必须完成所有 P0 任务；双人场景下确认私有预览、原子写入、冲突处理与撤销；生成失败不得修改已有作品。音乐建议的最终质量判断以用户任务测试为准。
