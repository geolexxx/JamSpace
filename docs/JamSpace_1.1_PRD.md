# JamSpace 1.1 产品需求文档

- **版本：** 1.1 PRD v1.0
- **状态：** 待产品、设计、工程评审
- **发布主题：** 邀请共创 → 完成作品 → 导出与分享 → AI 辅助继续创作
- **目标用户：** 2–4 人远程共同制作音乐草稿的小组
- **平台：** 桌面浏览器创作；桌面和移动浏览器均可打开作品试听页

## 0. 一页概览

JamSpace 目前已有实时音符编辑、轨道控制、Pattern 编排和浏览器本地播放能力。1.1 要补齐三个闭环：

1. **协作入口：** 用户能创建私有项目、邀请伙伴、设置查看或编辑权限，并清楚知道谁在线。
2. **交付出口：** 用户能把当前编排导出为音频，也能发布一个可试听、可撤销的作品链接。
3. **AI 协作：** AI 根据小组已有内容提出可编辑的 Bass 方案；人先试听，再决定是否加入共享作品。

**1.1 的完成定义：** 创建者发出邀请；第二人成功加入并修改项目；两人共同试听；创建者导出 WAV，并发布一个他人可打开的试听链接；其中至少一次 AI 建议可被试听和接受。以上每一步均有明确权限、失败处理和数据记录。

## 1. 现状、依据与待验证假设

### 1.1 现状

- 首页直接列出全部 Session，进入前只需填写昵称；客户端订阅全部公开表。当前没有项目访问范围、成员角色和专用邀请入口。[现有首页](../client/src/components/JoinModal.tsx) · [订阅逻辑](../client/src/App.tsx) · [服务端数据表](../server/src/lib.rs)
- 音乐由每个浏览器根据共享音符数据本地合成；目前没有导出音频或发布作品的流程。[播放调度](../client/src/audio/scheduler.ts) · [乐器实现](../client/src/audio/instruments.ts)
- 当前“Sync”共享的是播放开关和 BPM。1.1 的共同试听验收需测量实际播放偏移，不能只以两端按钮状态一致作为通过条件。[播放状态](../server/src/lib.rs)
- 现有 AI Jam Partner 草案明确了“私有预览 → 人工接受 → 批量写入”的基本交互。[AI 功能草案](./JamSpace_AI_Jam_Partner_PRD.md)

### 1.2 外部参考及采用方式

Figma 的分享面板将邀请对象、访问范围、查看／编辑权限与复制链接集中在一个入口；Miro 也在画布右上角提供 Share，并区分定向邀请和链接访问。JamSpace 借鉴这套**可见的权限结构**，并增加音乐产品需要的“发布试听版本”。[Figma 分享说明](https://help.figma.com/hc/en-us/articles/360040531773-Share-files-and-prototypes) · [Miro 分享说明](https://help.miro.com/hc/en-us/articles/360017730813-Sharing-boards-and-inviting-collaborators)

### 1.3 待验证假设

- 清晰的邀请入口和权限说明会提高“创建项目后成功邀请第二人”的比例。
- 音频导出和试听链接会提高用户完成、复访和分享作品的意愿。
- 局部、可编辑的 AI 建议比一次生成整首音频更适合 JamSpace 的多人共创流程。

这些是假设；1.1 内测必须通过行为数据和用户访谈验证。

## 2. 用户与核心任务

| 用户 | 当前任务 | 1.1 所需结果 |
| --- | --- | --- |
| 项目创建者 | 发起一段音乐创作 | 快速建项目、邀请伙伴、控制权限、交付作品 |
| 共同创作者 | 收到朋友邀请 | 明白自己的权限，进入正确项目，立即看到并编辑共享内容 |
| 听众 | 收到作品链接 | 不注册也能打开、播放；知道是否允许下载 |

**主要使用场景：** 两位朋友异地做一段 30–90 秒的 beat。A 建项目并邀请 B；B 写鼓，A 写旋律；AI 给出 Bass 候选；两人调整后，A 导出 WAV 并发布试听链接。

## 3. 目标、指标与范围

### 3.1 产品目标

1. 把“创建项目到第二人开始编辑”的路径变得清楚、可控。
2. 把项目内容转化为可带走的音频和可转发的试听版本。
3. 让 AI 缩短从第一段节奏到可试听完整片段的时间，同时保留人对作品的决定权。

### 3.2 核心指标

| 指标 | 定义 | 1.1 内测目标（提案） |
| --- | --- | --- |
| 双人共创完成率 | 新项目中，7 天内至少两位不同用户编辑且共同试听一次的比例 | ≥ 30%；首轮内测后复核 |
| 邀请成功率 | 创建者发出邀请后，7 天内被邀请者进入项目的比例 | ≥ 60% |
| 音频导出成功率 | 发起有效导出后成功生成并下载文件的比例 | ≥ 95% |
| 作品链接可播放率 | 有效分享链接打开后成功播放的比例 | ≥ 99% |
| AI 候选接受率 | 至少试听一个候选的生成会话中，最终接受一个候选的比例 | ≥ 25% |

**保护性指标：** 无权限访问成功次数为 0；导出文件截断或明显缺轨次数为 0；AI 操作造成既有音符丢失次数为 0。目标数值是内测判断线，发布前结合真实基线复核。

### 3.3 1.1 范围

**包含：** 私有项目、项目首页、邀请与角色、链接权限、在线状态、WAV 导出、作品发布试听页、发布链接撤销、AI Bass 候选、预览与接受、相关埋点和错误处理。

**暂不包含：** 完整 DAW 功能、音频录制、MP3、分轨导出、公开作品广场、社交评论、支付、AI 整曲生成、自然语言任意编辑、团队／组织层级权限。

## 4. 信息架构与主要流程

### 4.1 页面与入口

| 页面／面板 | 主要内容 | 主操作 |
| --- | --- | --- |
| 项目首页 | “我的项目”“与我共享”、最近打开时间、参与者头像、项目状态 | 创建项目、进入项目、打开分享设置 |
| 创作空间顶部 | 项目名、在线成员、播放控制、**邀请协作**、**导出／发布** | 协作、创作、交付 |
| 分享面板：协作 | 定向邀请、成员及角色、项目链接访问范围 | 邀请、复制项目链接、调整／撤销权限 |
| 导出／发布面板 | 导出 WAV、查看导出状态、发布试听版本、管理已发布链接 | 下载音频、复制试听链接、撤销发布 |
| 作品试听页 | 标题、创建者、时长、播放按钮、版本日期、可选下载按钮 | 播放、按权限下载 |
| AI 面板 | 目标小节、方向、三个候选、私有试听和预览 | 生成、试听、接受或取消 |

### 4.2 流程 A：邀请共创

创建者建私有项目 → 创作空间顶部点击“邀请协作” → 输入邮箱或开启有期限的编辑邀请链接 → 指定“可编辑” → 对方打开邀请并登录／确认昵称 → 进入对应项目 → 双方看到准确的在线状态与编辑更新。

### 4.3 流程 B：导出与分享作品

有权限的成员点击“导出／发布” → 预览当前编排时长 → 导出 WAV → 下载到本地。项目创建者也可点击“发布试听版本” → 系统固定当前作品快照并生成音频 → 返回专用试听链接 → 听众打开链接播放；创建者可随时撤销该链接。

**项目链接与作品链接必须明确区分：** 项目链接打开可协作的工作空间，受成员及项目链接权限约束；作品链接打开某次发布的试听版本，不能进入编辑器。

### 4.4 流程 C：AI 协作

可编辑成员在当前 Pattern 的 Bass 轨道点击“AI 补 Bass” → 选择 1–4 小节及“稳定／律动／跳跃” → 获得三个私有候选 → 分别试听 → 接受一个候选 → 音符整组加入共享项目，其他成员立即可见并可继续编辑。

## 5. 功能需求 A：协作入口与权限

### 5.1 身份与项目可见性

- **COL-01** 创建者与可编辑成员使用邮箱免密登录，以便在更换设备后找回自己的项目与权限；首次进入设置显示昵称。作品试听页允许匿名访问。
- **COL-02** 新项目默认“仅受邀成员可访问”。首页仅显示用户有权访问的项目；未授权者不得通过数据库订阅、项目 ID 或直链获取内容。
- **COL-03** 现有公开 Session 在迁移前作为只读演示数据单独处理；不得根据昵称或轨道归属自动认领创建者。上线前确认归属或归档。
- **COL-04** 项目创建成功后进入创作空间，首次进入可看到“邀请伙伴一起创作”的轻提示；提示可关闭，之后不遮挡编辑。

### 5.2 分享面板

- **COL-05** 创作空间右上角固定“邀请协作”按钮；项目首页卡片菜单提供同一入口。
- **COL-06** 面板顶部可输入邮箱定向邀请，指定“可查看”或“可编辑”；重复邀请、无效邮箱、已是成员要有明确反馈。
- **COL-07** 面板列出创建者和已加入／待接受成员，显示昵称、邮箱掩码或邀请状态、角色；创建者能改角色和移除成员。
- **COL-08** 面板底部提供项目链接访问范围：**仅受邀者**（默认）、**持链接可查看**、**持链接可编辑**。开启“可编辑”需创建者明确选择；编辑链接默认 7 天过期，可提前撤销或重新生成。编辑者通过链接进入后需登录。
- **COL-09** 复制链接后显示“已复制”反馈，并在面板内明确写出链接当前权限及到期时间。权限变更后，旧链接的访问结果必须即时更新；撤销的链接不能继续进入。
- **COL-10** 成员角色：创建者、可编辑、可查看。只有创建者可管理成员、项目链接和作品发布；可编辑者可改音乐、使用 AI、共同播放及导出；可查看者可查看／试听项目，不可改动或导出。
- **COL-11** 所有服务端写操作均检查项目角色，包括音符、轨道、Pattern、编排、共享播放和 AI 接受；现有连接在角色被撤销后也不能继续读写。
- **COL-12** 在线状态基于实际连接及超时心跳，离线后及时消失；项目首页与创作空间的在线人数一致。

### 5.3 权限矩阵

| 操作 | 创建者 | 可编辑 | 可查看 | 匿名作品听众 |
| --- | :---: | :---: | :---: | :---: |
| 查看项目、在项目内试听 | ✓ | ✓ | ✓ | — |
| 编辑音符／轨道／编排、控制共同播放 | ✓ | ✓ | — | — |
| 生成与接受 AI 建议 | ✓ | ✓ | — | — |
| 导出项目 WAV | ✓ | ✓ | — | — |
| 邀请成员、修改项目权限 | ✓ | — | — | — |
| 发布或撤销作品链接 | ✓ | — | — | — |
| 打开已发布作品并试听 | ✓ | ✓ | ✓ | ✓ |

**异常验收：** 过期邀请、已撤销链接、无权限直链、成员角色在页面打开期间被降级、浏览器刷新后重入，都必须给出正确的访问结果和清晰提示。

## 6. 功能需求 B：音频导出与作品分享

### 6.1 WAV 导出

- **EXP-01** 从当前项目的完整 Arrangement 导出一次播放的混音，按段落顺序包含空白小节，尾部保留乐器自然衰减（上限 2 秒）。无可播放音符时禁用导出并说明原因。
- **EXP-02** 首版输出 **44.1 kHz、16-bit、立体声 WAV**。文件名采用“项目名_YYYY-MM-DD.wav”，过滤不安全文件名字符。
- **EXP-03** 导出使用点击时的项目快照：Pattern、音符、BPM、拍号、轨道静音及共享音量；其他人后续编辑不改变该次文件。个人试听音量不影响导出。
- **EXP-04** 导出前显示预计时长；渲染时显示“正在生成”状态，若渲染方案能准确提供进度再显示百分比；支持取消及失败重试。首版支持最长 5 分钟；超限时解释限制并引导缩短编排。
- **EXP-05** 导出文件从头到尾可播放，不截断最后一个音符，轨道静音和音量与共享试听一致，无明显削波、缺轨或异常静音。
- **EXP-06** 导出只在有权限用户的浏览器产生下载文件；未经发布，不生成可公开访问的音频地址。

**技术可行性检查：** 浏览器离线音频渲染可输出音频缓冲区，但当前 JamSpace 同时使用 Tone.js 采样器和原生 Web Audio 合成，并从外部地址加载部分采样。开发前须验证两类乐器在离线渲染中的声音一致性、资源许可及跨域加载，必要时统一渲染路径与采样资源。[Tone.js Offline 文档](https://tonejs.github.io/docs/14.5.40/fn/Offline) · [Web Audio 离线渲染文档](https://developer.mozilla.org/en-US/docs/Web/API/OfflineAudioContext)

### 6.2 作品发布与分享

- **PUB-01** 只有创建者能发布。发布时固定项目快照并生成音频；发布成功前不显示可复制的作品链接。
- **PUB-02** 每次发布形成一个独立的、不可编辑的版本及其链接。项目后续编辑不改变已发布版本；“发布新版本”会产生新链接，旧链接由创建者决定保留或撤销。
- **PUB-03** 试听页展示项目标题、创建者显示名、发布时间、时长与播放控件；无需登录即可播放。1.1 不展示项目轨道、成员邮箱或编辑入口。
- **PUB-04** 创建者可设置该版本是否显示“下载 WAV”按钮；默认关闭。关闭按钮不能阻止有权试听的人录制声音，界面不应暗示这是数字版权保护。
- **PUB-05** 创建者可在“已发布版本”列表复制链接或撤销版本；撤销后链接显示“此作品已停止分享”，新的播放请求被拒绝。已下载或已录制的音频无法远程收回。
- **PUB-06** 分享链接应足够难以猜测；音频资源请求需验证有效的发布版本，不能凭猜测到的静态文件地址绕过撤销状态。
- **PUB-07** 导出或发布失败不改变项目；用户可重试。发布、重新发布及撤销都要有明确结果反馈。

## 7. 功能需求 C：AI 协作

### 7.1 首版功能

- **AI-01** 入口在当前 Pattern 的 Bass 轨道；一次针对连续 1–4 小节。目标范围已有 Bass 音符时不自动覆盖。
- **AI-02** 用户选择“稳定／律动／跳跃”；当已有旋律音符时作为参考；若没有旋律参考，提示用户选择调性。
- **AI-03** 一次生成三个结构化音符候选，每个候选包含位置、音高、时值和力度；服务端验证范围、可演奏音域、时值及重复音符。
- **AI-04** 未接受的候选只在发起人本地预览和试听，其他成员看不到，也不影响共同播放。
- **AI-05** “加入作品”时再次检查参考内容与目标范围。若队友已修改相关内容，提示冲突并要求重新生成；成功时整组写入音符，不出现只写入一部分的状态。
- **AI-06** 被接受的音符标记“AI 建议，由〈用户名〉加入”，之后可正常编辑；未被他人改动时支持整组撤销，已被他人改动时阻止整组撤销并提示冲突。
- **AI-07** 失败、超时、无有效候选及超配额都保留原作品，提供可理解的提示；AI 服务密钥与额度控制在服务端。
- **AI-08** 首次使用时说明将发送当前选定片段的音乐数据用于生成，不发送其他项目或成员邮箱；记录用户同意及模型调用成本。

**内测性能目标：** 90% 的有效请求在 15 秒内产生可试听候选，技术验证后复核。详细交互和数据校验沿用 [AI Jam Partner 草案](./JamSpace_AI_Jam_Partner_PRD.md)，本节为 1.1 发布范围的准绳。

## 8. 跨功能要求与边界

- **NFR-01 数据与权限：** 取消“全部项目公开订阅”的现状；权限必须在服务端生效，前端隐藏按钮不能代替访问控制。分享链接与 AI 请求需要限流和可撤销能力。
- **NFR-02 一致性：** 导出、发布和 AI 接受均以可识别的项目版本为依据；多人同时编辑时不产生混合快照或部分写入。
- **NFR-03 播放：** 共同试听与本地试听分离；用户切换个人模式或预览 AI 候选，不得停止其他人的共同播放。测量双端播放偏移并据此设定或调整同步体验文案。
- **NFR-04 恢复：** 断线重连后保留已确认的编辑、权限和发布状态；正在渲染的导出或生成给出明确恢复／重试状态。
- **NFR-05 易用性：** 分享权限文字清晰；所有主要按钮有键盘可达的名称和焦点状态；试听页适配移动浏览器。
- **NFR-06 观测：** 记录关键路径的成功、失败、耗时和权限拒绝，不在分析事件中存储完整音符或邀请邮箱。

## 9. 事件埋点与验收场景

**主要事件：** `project_created`、`invite_sent`、`invite_accepted`、`project_joined`、`permission_changed`、`coedit_started`、`export_started`、`export_succeeded`、`export_failed`、`publish_started`、`publish_succeeded`、`share_opened`、`share_play_succeeded`、`share_revoked`、`ai_generate_started`、`ai_candidate_previewed`、`ai_candidate_accepted`、`ai_generate_failed`、`ai_conflict`。

**端到端验收：**

1. A 创建私有项目；陌生用户用猜测的项目 ID 无法查看内容。
2. A 邀请 B 编辑、邀请 C 查看；B 能写鼓点，C 不能改音符或导出。
3. A 和 B 同时编辑同一 Pattern，双方实时看到结果；B 离开后在线状态消失。
4. B 生成并私下试听 AI Bass；A 在 B 接受前看不到候选；接受后双方看到完整音符组。
5. A 导出 WAV。导出期间 B 继续编辑；文件仍对应 A 点击导出时的快照。
6. A 发布试听版本，匿名用户 D 能播放但不能进入项目；A 撤销后 D 无法继续打开或读取音频。
7. B 的编辑权限在已打开页面时被撤销；下一次读写请求立即被拒绝，并提示刷新或联系创建者。

## 11. 发布门槛与主要风险

**发布门槛：** 所有 P0 项完成；第 9 节端到端场景通过；没有已知的越权读写、作品数据丢失或公开音频撤销失效；导出与试听页达到第 3 节内测目标，或由 PM 与工程明确记录偏差和处理方案。

| 风险 | 对用户的影响 | 处理顺序 |
| --- | --- | --- |
| 当前数据表公开订阅、写操作缺少项目权限 | 私有项目形同虚设 | 身份与权限必须先于邀请入口发布 |
| 当前乐器混用采样器和原生音频合成 | WAV 可能与实时试听不一致 | 先做 D01 技术验证，再定导出实现 |
| 当前共同播放仅同步开关与 BPM | 两端可能听到不同节拍位置 | 在 1.1 中测量并修正或收紧“同步”文案 |
| AI 候选生成期间有人编辑 | 接受时覆盖队友新内容 | 服务端快照冲突检查与整组写入 |
| 区分项目链接与作品链接不清 | 用户误把编辑权限给听众 | 文案、界面分区和 A03 用户走查 |
